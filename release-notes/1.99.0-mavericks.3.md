On 10.9, `rustc` and `cargo` now link with Mavergreen clang22 by default, so they work without
Apple's Command Line Tools. Before, every link used `cc`, which on a 10.9 Mac without the Command
Line Tools is only a stub that can't link anything.

- **Install clang22 first.** This pkg now refuses to install without it. Any clang22 from
  `22.1.1-mavericks.7` on works. A rust unpacked somewhere other than `/usr/local/mavergreen`
  (as fd's and rg's builds do) uses the installed clang22.
- **Naming a linker still wins.** That includes `cc` if you have the Command Line Tools: set
  `CARGO_TARGET_X86_64_APPLE_DARWIN_LINKER=cc`, or pass `-C linker=cc`.
- If clang22 is missing, broken, or too old to link the 10.9 back-fills, `rustc` says so and names
  both fixes, instead of failing inside the linker. `rustc --version` and cargo's own checks work
  regardless.
- Linking through clang22, whether by default or by name, `rustc` uses clang22's own 10.9 SDK when
  `SDKROOT` isn't set, so it never runs Apple's `xcrun` stub to look for one.
