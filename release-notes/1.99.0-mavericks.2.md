`rustc` now links cleanly when Mavergreen clang22's `clang++` is the target linker
(`CARGO_TARGET_X86_64_APPLE_DARWIN_LINKER`), on 10.9 with `clang22` and on a modern Mac with
`clang22-cross`. Such a linker already links the 10.9 back-fills, so `rustc` now leaves them to it.
Before, every link failed with `duplicate symbol`. This needs clang22 `22.1.1-mavericks.7` or later.

The 10.9 back-fills now come from Recaulk, the family's back-fill library, in place of
macports-legacy-support and this repo's own copies. Programs linked with the default `cc` still get
every back-fill, as before.
